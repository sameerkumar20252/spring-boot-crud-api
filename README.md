# Spring Boot Student CRUD API

A RESTful API for managing student records built using **Spring Boot, Spring Data JPA, Hibernate, and MySQL**. This project supports standard CRUD operations and soft deletion, allowing student records to be marked as deleted without physically removing them from the database.

## Features

- Create a new student record
- Retrieve a student by ID
- Retrieve all student records
- Update student details
- Delete a student using the regular delete operation
- Delete all student records using the regular delete operation
- **Soft Delete:** Mark a student as deleted without permanently removing the database record
- Automatically generate student IDs using JPA
- Test REST API endpoints using Postman

## Tech Stack

- **Language:** Java
- **Framework:** Spring Boot
- **ORM:** Hibernate
- **Data Access:** Spring Data JPA
- **Database:** MySQL
- **Build Tool:** Maven
- **API Testing:** Postman
- **IDE:** IntelliJ IDEA

## Student Entity Structure

The `Student` entity represents a student record in the MySQL database.

| Attribute | Data Type | Description |
|---|---|---|
| `id` | `Long` | Unique student ID, automatically generated by the database |
| `name` | `String` | Student's full name |
| `age` | `int` | Student's age |
| `email` | `String` | Student's email address |
| `rollNo` | `int` | Student's roll number |
| `subject` | `String` | Student's subject |
| `deleted` | `boolean` | Indicates whether the student has been soft-deleted |

### Example Student JSON

```json
{
  "id": 1,
  "name": "Sameer Kumar",
  "age": 20,
  "email": "sameer@example.com",
  "rollNo": 101,
  "subject": "Computer Science",
  "deleted": false
}
```

**Note:** The `id` is automatically generated when a student is created, so you normally do not need to include it in a POST request. The `deleted` field should be `false` for a new student.

## Getting Started

### Prerequisites

Make sure you have installed:

- JDK 17 or higher, compatible with your project's `pom.xml`
- MySQL Server
- Maven, or the Maven Wrapper included in the repository
- Git

### 1. Clone the Repository

```bash
git clone https://github.com/sameerkumar20252/spring-boot-crud-api.git
cd spring-boot-crud-api
```

### 2. Create the MySQL Database

Open MySQL or DBeaver and execute:

```sql
CREATE DATABASE student_crud_db;
```

### 3. Configure Database Connection

Configure your database connection in `src/main/resources/application.properties`.

Example configuration:

```properties
spring.application.name=crudSpringBootDemo

spring.datasource.url=jdbc:mysql://localhost:3306/student_crud_db
spring.datasource.username=${DB_USERNAME:root}
spring.datasource.password=${DB_PASSWORD}

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

Set the `DB_PASSWORD` environment variable to your MySQL password. Alternatively, use your own local database credentials in your uncommitted configuration file.

**Security:** Never commit your actual database password or other sensitive credentials to GitHub.

### 4. Run the Application

On Windows, open a terminal in the project directory and run:

```bash
mvnw.cmd spring-boot:run
```

On Linux or macOS, run:

```bash
./mvnw spring-boot:run
```

Once the application starts successfully, the base URL is:

```text
http://localhost:8080
```

## API Endpoints

All endpoints use the following base URL:

```text
http://localhost:8080/api/students
```

| HTTP Method | Endpoint | Parameters | Description |
|---|---|---|---|
| `POST` | `/create` | JSON request body | Create a new student |
| `GET` | `/get` | `id` | Retrieve a student by ID |
| `GET` | `/getAll` | None | Retrieve all students |
| `PUT` | `/update` | `id` and JSON request body | Update student details |
| `DELETE` | `/delete` | `id` | Delete a student using the regular delete operation |
| `DELETE` | `/deleteAll` | None | Delete all student records using the regular delete operation |
| **`PATCH`** | **`/delete-soft`** | **`id`** | **Soft-delete a student without physically removing the record** |

### 1. Create a Student

**Method:** `POST`

**URL:**

```http
http://localhost:8080/api/students/create
```

**Request Body:**

```json
{
  "name": "Sameer Kumar",
  "age": 20,
  "email": "sameer@example.com",
  "rollNo": 101,
  "subject": "Computer Science",
  "deleted": false
}
```

**Expected result:** `201 Created`, with the created student returned in the response body.

### 2. Retrieve a Student by ID

**Method:** `GET`

**URL:**

```http
http://localhost:8080/api/students/get?id=1
```

The `id` is passed as a query parameter.

**Expected result:** `200 OK` if the student is found, or `404 Not Found` if the service returns `null`.

### 3. Retrieve All Students

**Method:** `GET`

**URL:**

```http
http://localhost:8080/api/students/getAll
```

**Expected result:** `200 OK` with a list of students, or `404 Not Found` if the returned list is empty.

### 4. Update Student Details

**Method:** `PUT`

**URL:**

```http
http://localhost:8080/api/students/update?id=1
```

**Request Body:**

```json
{
  "name": "Sameer Kumar",
  "age": 21,
  "email": "sameer.updated@example.com",
  "rollNo": 101,
  "subject": "Java Backend Development",
  "deleted": false
}
```

**Expected result:** `200 OK` if the student is found and updated, or `404 Not Found` if the service returns `null`.

### 5. Delete a Student

**Method:** `DELETE`

**URL:**

```http
http://localhost:8080/api/students/delete?id=1
```

This endpoint calls the regular `deleteStudent()` service method.

**Expected success response:**

```text
Record Deleted
```

**Expected status:** `200 OK` on success, or `404 Not Found` if the student is not found.

### 6. Delete All Students

**Method:** `DELETE`

**URL:**

```http
http://localhost:8080/api/students/deleteAll
```

This endpoint calls the `deleteAllStudent()` service method.

**Expected success response:**

```text
All student records deleted successfully
```

**Warning:** This endpoint uses your regular delete-all service method. Whether records are physically removed depends on how that method is implemented.

### 7. Soft-Delete a Student

**Method:** `PATCH`

**URL:**

```http
http://localhost:8080/api/students/delete-soft?id=1
```

This endpoint calls `studentService.deleteStudentSoftly(id)`.

Instead of physically removing the student record, the service should update the student's `deleted` field to `true`.

**Example record before soft deletion:**

```json
{
  "id": 1,
  "name": "Sameer Kumar",
  "age": 20,
  "email": "sameer@example.com",
  "rollNo": 101,
  "subject": "Computer Science",
  "deleted": false
}
```

**Example record after soft deletion:**

```json
{
  "id": 1,
  "name": "Sameer Kumar",
  "age": 20,
  "email": "sameer@example.com",
  "rollNo": 101,
  "subject": "Computer Science",
  "deleted": true
}
```

These JSON objects illustrate the expected database state. They are not necessarily the actual response bodies returned by the soft-delete endpoint.

**Expected success response:**

```text
Record deleted
```

**Expected status:** `200 OK` on success, or `404 Not Found` if the service returns `false`.

**Important:** For a complete soft-delete implementation, ensure your service updates `deleted = true` instead of physically removing the record. Also ensure your GET operations exclude soft-deleted records if that is the intended behavior.

## Testing

You can test the API using [Postman](https://www.postman.com/).

For each request:

1. Select the appropriate HTTP method.
2. Enter the endpoint URL.
3. For POST and PUT requests, select **Body → raw → JSON**.
4. Enter the request body where required.
5. Click **Send**.
6. Verify the HTTP status code and response.

Example command to retrieve a student:

```bash
curl "http://localhost:8080/api/students/get?id=1"
```

Example command to soft-delete a student:

```bash
curl -X PATCH "http://localhost:8080/api/students/delete-soft?id=1"
```
